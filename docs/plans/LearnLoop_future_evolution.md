# LearnLoop 未来演进规划

## 1. 文档目的

本文记录不纳入第一版的演进方向。它们不是必须同时实现的功能，而是当真实使用数据证明第一版遇到瓶颈时的候选方案。第一版范围以 `LearnLoop_v1_project_plan.md` 为准。

演进原则：

- 先用真实指标证明问题，再增加基础设施。
- 保持领域接口稳定，替换基础设施实现而不是重写 Agent。
- 优先提高可靠性和评测质量，再增加 Agent 数量。
- 每个阶段都保留本地单用户模式。

## 2. 数据库与检索演进

### 2.1 SQLite 到 PostgreSQL

触发条件：

- 需要多用户并发写入。
- 需要部署为公开在线服务。
- 单 Worker 和 SQLite 写锁成为可测量瓶颈。
- 需要更复杂的分析、备份和高可用能力。

演进方案：

- 业务数据库迁移到 PostgreSQL。
- LangGraph Checkpoint 迁移到 `AsyncPostgresSaver`。
- Repository 接口保持不变。
- 使用 Alembic 和专用迁移工具导出 SQLite 数据并导入 PostgreSQL。
- 迁移前后执行记录数、外键和 Hash 对账。

### 2.2 向量检索演进

触发条件：

- 资料块达到数十万级。
- Python 全量/候选向量计算延迟不可接受。
- 需要多用户隔离或高并发检索。

候选方案：

1. PostgreSQL + pgvector：优先选择，保持单数据库。
2. Qdrant：需要独立向量服务和更强过滤时采用。
3. 本地 sqlite-vec/LanceDB：希望继续本地运行但需要更快索引时评估。

`Retriever`、`KeywordIndex` 和 `VectorIndex` 接口必须使迁移对 Agent 节点透明。

### 2.3 知识图谱演进

第一版用 `knowledge_nodes` 和 `knowledge_edges`。只有当图遍历、路径查询和关系规模超出关系表能力时才评估 Neo4j。不要仅为了展示“知识图谱”增加独立数据库。

## 3. 文件存储演进

触发条件：

- 多设备访问。
- 在线部署。
- 资料量超过单机备份能力。
- 需要对象版本、生命周期或远端备份。

实现顺序：

1. 本地目录。
2. 可选 MinIO 自托管。
3. S3 或兼容对象存储。

通过 `DocumentStorage` 接口替换实现。对象 ID、Hash 和相对逻辑路径保持稳定，业务表不得依赖供应商 URL。

## 4. 后台任务演进

### 4.1 多 Worker

触发条件：

- PDF、Embedding 或评测任务排队时间明显增长。
- 单 Worker 导致交互任务被批处理任务阻塞。
- 在线服务需要隔离不同工作负载。

演进方案：

- 将 Job Backend 抽象为接口。
- 使用 Redis + Taskiq、Dramatiq 或 Celery 等持久队列方案。
- 将资料解析、Embedding、Agent Run 和评测拆成不同队列。
- 增加死信队列、优先级、取消、租约和任务指标。
- 定时调度器仍只负责入队，不直接执行耗时任务。

### 4.2 长任务与资源隔离

- 为代码执行、文档解析和模型调用设置独立并发限制。
- 支持任务取消和进度上报。
- 对相同文件 Hash 和相同 Embedding 配置做幂等去重。
- 对恢复中的 LangGraph Run 避免重复副作用。

## 5. 部署演进

第一版不要求 Docker。未来在线或团队部署时按以下顺序演进：

1. 提供可选 Dockerfile。
2. 提供 Docker Compose 作为本地服务化方案。
3. 自动化数据库迁移、健康检查和备份。
4. 只有存在明确扩缩容需求时再考虑 Kubernetes。

本地模式始终保留原生启动方式，不能让容器成为导入个人数据和运行 LearnLoop 的唯一方式。

## 6. 客户端演进

### 6.1 PWA 能力

- Service Worker 离线缓存。
- Web Push 学习和复习提醒。
- 网络恢复后的请求重放。
- 移动端学习会话布局。

### 6.2 桌面端

只有在需要深度文件系统集成、系统托盘或本地模型管理时，再评估 Tauri。桌面端应复用现有 Web UI 和 HTTP API，而不是重新实现业务逻辑。

### 6.3 原生移动端

当 PWA 无法满足通知、离线或设备能力时再评估 React Native/Flutter。第一版不维护第三套客户端代码。

## 7. 多用户与身份系统

触发条件：

- 需要公开部署或家庭/小组共享。
- 需要跨设备同步。

演进内容：

- 注册、登录、会话和密码重置。
- OAuth/Passkey。
- 数据行级用户隔离。
- 资源配额和模型费用限制。
- 数据导出、删除和账户注销。
- 管理操作审计。

由单用户迁移时，第一版所有领域表已包含 `user_id`，避免后续大规模重构。

## 8. Agent 架构演进

### 8.1 专业化子 Agent

满足以下条件才拆分：

- 独立的上下文和工具集合。
- 独立的权限边界。
- 可以单独评测。
- 拆分能减少上下文或提高成功率。

候选子 Agent：

- Curriculum Planner：课程和知识依赖规划。
- Resource Curator：资料筛选、去重和质量评价。
- Tutor Agent：讲解、提问和补救教学。
- Exercise Agent：生成不同题型。
- Evaluator Agent：Rubric 评分和误区识别。

子 Agent 优先实现为 LangGraph 子图，通过结构化状态通信，不使用无边界的自然语言群聊。

### 8.2 模型路由

- 简单分类和抽取使用低成本模型。
- 规划和开放题评分使用更强模型。
- Embedding 独立路由。
- Provider 失败时按能力兼容性降级。
- 根据离线评测而不是主观印象选择模型。

### 8.3 本地模型

- 通过 Ollama、vLLM 或 OpenAI-compatible 接口接入。
- 为不同本地模型维护能力声明：Tool Calling、JSON Schema、上下文长度。
- 不假设所有模型都能可靠调用工具。
- 为本地模式提供更严格的解析、修复和回退测试。

### 8.4 更高级的学习策略

- 基于知识追踪模型更新掌握度。
- 根据遗忘、难度和目标期限联合选题。
- 生成式练习与题库检索结合。
- 主动发现学习计划中的知识缺口。
- 利用用户长期反馈优化难度和讲解风格。

## 9. 代码执行沙箱

代码题进入稳定阶段后增加独立 Sandbox 接口：

```text
CodeSandbox
├── create(language, limits)
├── run(code, tests)
├── read_result(run_id)
└── destroy(sandbox_id)
```

安全要求：

- 默认禁用网络。
- 限制 CPU、内存、进程数、文件大小和执行时间。
- 使用临时工作目录。
- 禁止访问 LearnLoop 数据目录和 API Key。
- 保存测试结果，不保存不必要的用户源码副本。

没有可靠隔离前，只允许受控解释器或模拟代码题；不要直接在 API 进程执行模型生成的任意代码。

## 10. 资料能力演进

- DOCX、PPTX、EPUB 和表格解析。
- 图片 OCR 和公式识别。
- 音频/视频转录与时间戳引用。
- 网页多页抓取和更新检测。
- 资料质量、重复和冲突检测。
- 版本变更后仅重算受影响分块。

任何新增格式都要建立解析准确率和引用定位测试，不能只以“能够导入”为完成标准。

## 11. 外部集成演进

候选集成：

- CalDAV、Google Calendar：学习日程。
- Anki：卡片导入导出。
- Obsidian：Markdown 知识库。
- GitHub：代码学习目标和项目练习。
- 浏览器扩展：保存网页资料。
- 邮件/Web Push：提醒与周报。

所有写操作应先预览并允许确认；外部调用使用幂等键、最小权限和审计日志。

## 12. 可观测性演进

第一版使用本地表和结构化日志。需要跨服务追踪时增加：

- OpenTelemetry Trace、Metric 和 Log。
- Langfuse 或 LangSmith 作为可选 Agent 调试平台。
- Prompt、模型、数据集和代码版本关联。
- Trace 回放和失败聚类。
- Token、费用、P50/P95 延迟和成功率面板。

可观测性数据应默认脱敏，禁止记录 API Key、完整隐私资料或模型隐藏推理过程。

## 13. 评测演进

- 将个人标注样本扩展为版本化公开评测集。
- 建立不同学科的分层测试集。
- 对 Tutor、Retriever、Planner、Evaluator 分模块评测。
- 增加 Prompt/模型 A/B 测试。
- 在 CI 中设置核心 Agent 指标回归阈值。
- 研究长期指标：知识保持率、计划完成率和用户纠正率。
- 增加安全评测：Prompt Injection、越权工具和恶意文件内容。

长期效果评测需要明确区分相关性和因果性，不能仅凭“使用后分数上升”断言 Agent 造成学习提升。

## 14. 隐私与安全演进

- 本地数据库和文件可选加密。
- 系统密钥链保存 API Key。
- 数据备份加密和恢复演练。
- 资料级权限和敏感标记。
- Prompt Injection 内容隔离。
- 外部工具最小权限。
- 数据保留和自动清理策略。
- 安全导出与彻底删除。

## 15. 产品能力演进

- 多学习目标优先级协调。
- 模板化学习路径。
- 学习计划分享但不分享私人作答。
- 教师或同伴审核入口。
- 无障碍与多语言界面。
- 个性化通知频率。
- 数据可视化和年度学习回顾。

这些产品能力应建立在稳定学习闭环和真实用户反馈之上，不能挤占第一版的 Agent 可靠性与评测工作。

## 16. 推荐演进顺序

### 第二版本：个人使用增强

- PWA 离线与通知。
- Anki/Obsidian/Calendar 集成。
- 更多资料格式。
- 安全代码沙箱。
- 本地模型支持。

### 第三版本：Agent 质量增强

- 专业化子图或子 Agent。
- 多模型路由。
- Trace 回放和失败分析。
- 评测 CI Gate。
- 更强知识追踪模型。

### 第四版本：在线与多用户

- PostgreSQL + pgvector。
- 对象存储。
- Redis 任务队列和多 Worker。
- 身份、配额和跨设备同步。
- 可选 Docker/云端部署。

在进入下一版本前，先为目标能力定义触发指标、迁移方案、回滚方案和验收测试。
